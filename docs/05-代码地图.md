> 读法：先记 **7 个层**，再记每层的 **2–4 个文件**，最后记文件里的 **3–5 个方法组**。
> 方法是"实现细节"，组是"记忆钩子"——面试时只报组名就能讲清架构。
>
> 本文是**速查版**（每方法一句话）；逐个方法的详细说明（做什么 / 输入输出 / 为什么这么写）见 `06-方法详解.md`。

## 0. 七层总览

| 层 | 文件 | 一句话职责 | 依赖方向 |
|---|---|---|---|
| L0 契约层 | `schema.py`、`semantics/registry.py`、`semantics/expr.py` | 定义"字段是什么、指标怎么算、公式怎么安全地算" | 不依赖任何上层 |
| L1 接入层 | `io_load.py` | 把脏 CSV / 试玩表变成统一 `Dataset` | 依赖 L0 |
| L2 统计层 | `statsx.py` | Bootstrap CI、Cohen's d、Mann-Whitney、样本量判定 | 纯数学，不依赖业务 |
| L3 计算层 | `semantics/compute.py` | 行级公式 → 聚合到（玩家×关卡）→ 出 `LevelMetrics` | 依赖 L0+L1+L2 |
| L4 诊断层 | `insights.py`、`diff.py`、`bench.py` | 规则引擎出"发现"；版本对比出"结论"；跨项目基准线出"位置" | 依赖 L3 |
| L5 呈现层 | `report.py`、`charts.py`、`export_excel.py` | 中间结构 → Markdown / 单文件 HTML / Excel / 图 | 依赖 L4 |
| L6 交互层 | `cards.py`、`cli.py`、`app.py` + `pages/` + `ui_common.py` | 问答卡片路由、命令行、Streamlit 多页界面 | 依赖 L4+L5 |

数据流向：`原始表 →(L1) Dataset →(L3) LevelMetrics →(L4) PulseCheck / VersionDiff / BenchCompare →(L5) Report`，L0/L2 是被全程调用的地基。

## L0 · 契约与口径层

### `schema.py` —— 字段字典（41 个规范字段）

| 组 | 成员 | 作用 |
|---|---|---|
| 字段定义 | `FieldSpec`（冻结 dataclass）+ 类内 `FIELDS` 列表 | 每个字段的英文名、类型、分组、人话解释、单位、层级、是否必填、合理区间 |
| 字段查询 | `explain_field(field_name)`、`fields_of_layer(layer)` | 按名字取解释；按层级（通用/品类/项目）取字段集——报告的"口径说明"直接读这里 |

### `semantics/registry.py` —— 指标本体（`metrics.yaml` 的内存表示）

| 组 | 成员 | 作用 |
|---|---|---|
| 数据类 | `MetricDef`（含 `required_fields`）、`ComponentDef`、`CompositeDef`、`RuleDef` | 指标 / 复合指标的分量 / 复合指标 / 规则的静态定义 |
| 解析与校验 | `Ontology.__init__`、`.load_from_yaml`、`.validate_formulas`（字段提取是一行式 `_fields_in`） | 解析 YAML，检查公式引用字段是否都存在、复合权重是否归一，返回告警列表 |
| 查询 | `.metric`、`.metrics_of_layer`、`.computable_ids(dataset)`、`.blocked_with_reason(dataset)` | 按 id / 层级取指标；**按当前数据判断哪些指标算得出来**——小样本场景的核心 |
| 导出与单例 | `.to_markdown`、`default_ontology`（文本清洗是一行式 `_clean`） | 导出口径文档（痛点①的交付物，`out/口径说明.md`）；全局单例避免重复解析 |

### `semantics/expr.py` —— 公式安全求值（不用 `eval`）

| 组 | 成员 | 作用 |
|---|---|---|
| 异常 | `ExprError` | 语法错、变量不在白名单、函数不在白名单时抛出 |
| 标量/Series 适配 | `apply_scalar_or_series` | 让同一个函数既能吃数字也能吃整列，返回类型保持一致 |
| 白名单函数 | `safe_div`、`_zscore`、`_max_ratio` + `FUNCTIONS` 表内一行式 | 安全除法（0 分母给 NaN）、标准化、占最大值百分比；abs/sqrt/log/round/min/max/clip/mean/median 直接写在表里的（原 `_clip`/`_mean`/`_median` 三个 def 已合并） |
| 求值引擎 | `_eval_node`、`safe_eval`、`check_formula` | 递归遍历 AST 只放行白名单节点；`safe_eval` 真算，`check_formula` 只验不算 |

## L1 · 数据接入层 `io_load.py`

| 组 | 成员 | 作用 |
|---|---|---|
| 列名归一 | `map_raw_column`（归一逻辑是一行式 `_norm`） | 去空格/括号/大小写差异，把"通关时长(s)"这类乱列名映射到规范字段 |
| 数据容器 | `Dataset`（dataclass） | 装规范化后的 `df` + 未映射列 + 来源信息 |
| — 规模属性 | `.n_rows`、`.n_players`、`.levels`、`.versions`、`.is_synthetic` | **行数是记录数，样本量是玩家数**，两者分开是防误判的关键 |
| — 切片与检查 | `.subset_by_version(version)`、`.has_fields(*cols)`、`.field_coverage()` | 切单版本；判断字段齐不齐；输出各字段缺失率表 |
| 读文件 | `read_file`（原 4 个 def 已合并） | CSV 按编码顺序试探；试玩登记表（表头在中间、上方有元信息行）走同一函数内的另一分支，失败退回普通表格 |
| 规范化 | `to_fact_table` | 列名映射 + 类型强转 + 派生字段 + 缺失兜底 + 异常值标记，脏数据的收口 |
| 对外入口 | `load_auto`（原 `load`/`load_many`/`load_dir` 已合并） | 唯一入口：文件单读、目录批量读，多文件按 玩家+版本+关卡 去重 |

## L2 · 统计底座 `statsx.py`

| 组 | 成员 | 作用 |
|---|---|---|
| 样本量判定 | `verdict_by_sample_size(n, min_n)` | 三档：够 / 勉强 / 不足，不足时全系统只说"方向参考"（原 `verdict_note` 已并入 `describe_sample`） |
| 单组描述 | `describe_sample` | 中位数 + Bootstrap 百分位 CI + 样本量 + 判定 + 一句话说明（原 `bootstrap_ci` 已合并） |
| 两组比较 | `compare_two_groups`、`explain_effect_size` | `compare_two_groups` 一次给出 Δ 中位数 + 差值 CI + Cohen's d + Mann-Whitney p + 诚实结论（原 `cohens_d`/`bootstrap_diff_ci`/`mannwhitney_p` 已合并）；`explain_effect_size` 把 d 翻成人话 |
| 格式化 | `fmt_num` | 空值统一显示破折号 |

> 核心判定逻辑：差值 CI 整体在 0 一侧才算 `beyond_noise`，否则一律"噪声内"。

## L3 · 指标计算层 `semantics/compute.py`

| 组 | 成员 | 作用 |
|---|---|---|
| 结果容器 | `LevelMetrics` | 逐关逐个指标的点估计 / CI / 样本量 / 判定 + 跳过原因 |
| — 取值 | `.value_at(metric, level)`、`.detail_at(metric, level)` | 只要数；要数+CI+判定 |
| 公式辅助 | `eval_formula_rows`（内含字段提取） | 对整张表套公式得行级 Series；顺带从公式反推依赖字段，缺哪列就跳过该指标（原 `_referenced_fields` 已合并） |
| 主计算 | `compute_level_metrics` | **三步**：行级公式 → 聚合到（玩家×关卡）→ Bootstrap。聚合单位错，结论就错 |
| 复合指标 | `compute_composites` | 按 YAML 里的分量与权重合成难度指数、流失风险等 |
| 视图 | `split_quadrants`、`player_level_matrix` | 客观×感知四象限（象限名与建议改查表）；玩家×关卡矩阵（供分组对比、分布图复用） |

## L4 · 诊断层

### `insights.py` —— 规则引擎（产出"发现"）

| 组 | 成员 | 作用 |
|---|---|---|
| 结果容器 | `Finding`（`.is_trustworthy`、`.to_row`）、`PulseCheck`（`.findings_by_severity`、`.findings_sorted`、`.findings_as_table`） | 一条发现（含严重度、证据、建议、是否可信）；一次体检的全部发现 + 排序/筛选/转表 |
| 调度 | `run_pulse_check` | 依次调用各规则、汇总发现、附逐关明细与归因分布 |
| 规则实现 | `detect_difficulty_jump`、`detect_threshold_breach`、`_detect_perception_gap` | 相邻关卡跳变（断崖/尝试骤增）；阈值类（卡关率/时间膨胀/准流失）；四象限背离（假性难度） |
| 曲线评估 | `describe_curve_shape`、`detect_curve_problem` | 判断整体形状是否"锯齿上升"，不是则给低优先级提示 |
| 分布统计 | `count_codes_by_level` | 编码字段占比通用统计（逐关 + 整体），卡关归因与三选一共用它、传不同码表（原 `_attribution`/`_choice_distribution` 两个包装层已合并） |

> 规则全部写在 `metrics.yaml` 的 `rules:` 里，代码只负责执行——改阈值不用改代码。

### `diff.py` —— 版本对比

| 组 | 成员 | 作用 |
|---|---|---|
| 结果容器 | `VersionDiff`（`.verdict_sentence`） | 对比表 + 结论句 + 曲线数据 |
| 行构造 | `_diff_row`（聚合函数是一行式 `_agg`） | 把两个版本的统计量拼成一行 14 键字典 |
| 主流程 | `version_diff` | 按关卡对齐逐项对比：Δ 中位数 + 差值 CI + d + p，自动检测并警告学习效应 |
| 结论生成 | `_conclusion_lines`（格式化是一行式 `fmt_num`） | 把显著项翻成人话结论 |

### `bench.py` —— 跨项目基准线（PlayBench）

| 组 | 成员 | 作用 |
|---|---|---|
| 常量与格式化 | `MIN_PROJECTS=3`、`MIN_DEVIATION_PCT=10.0`、`DEFAULT_METRICS`、`_UNITS`、`_slug`、`_fmtv` | 项目数不到 3 个不给基准线；偏离不到 10% 一律算"持平"；只比 7 个核心指标；数字按量级决定小数位；项目名转合法目录名 |
| 存档位置 | `bench_root`、`project_dir` | 根目录取 `PLAYBENCH_HOME` 或 `data/bench`；**一个项目一个目录**，这是隔离边界 |
| 数据结构 | `RunRecord`、`Baseline`（`.row_at`、`.is_trustworthy`）、`BenchCompare`（`.verdict_sentence`） | 一次存档（只留通用层点估计 + 曲线 + 发现，**不存原始行**）；基准线分位表与可信判定；对比结果与一句话结论 |
| 存取 | `save_run`、`load_runs`、`list_projects`、`latest_run_per_project` | 写一次体检；读全部存档；列项目清单；**每个项目只取最新一次**——一项目一票 |
| 建线 | `build_baseline` | 按（指标 × 关卡）跨项目算 P10/P25/P50/P75/P90，记下项目数与"基准可信" |
| 判定 | `judge_against_baseline`、`compare_to_baseline`、`_compare_conclusions` | 逐格判断位置（含"基准没离散度""偏离不到 10%"两种**不说高低**的情形）；整份对比 + 告警 + 结论句（按偏离幅度排序） |
| 辅助 | `_universal_metric_ids`、`_metric_name`、`_metric_direction`、`baseline_table_for_display` | 只取通用层指标；取中文名；取"越高越差 / 越高越好"方向；给表格补中文列 |

> 三条规矩：**一项目一票、只比通用层、项目数不到 3 个不给基准线**。完整说明见 `07-PlayBench-跨项目基准线.md`。

## L5 · 呈现层

### `report.py` —— 报告生成

| 组 | 成员 | 作用 |
|---|---|---|
| 块构造器（迷你 DSL） | `H`、`P`、`CALLOUT`、`TABLE`、`IMG`、`LIST`、`RAW`（七个一行式） | 报告先做成"块列表"中间结构，渲染器只认块；各构造器不再单占一个 def |
| 结果容器 | `Report`（`.save_files`） | 持有 Markdown/HTML 两种文本 + `meta["wide"]` 纯数值宽表，落盘返回路径字典（默认含 xlsx） |
| 编排 | `build_report`（章节编号是一行式 `_sec` + `_CN_NUM`） | 执行摘要 → 发现清单 → 逐关明细 → 可信度 → 口径 → 行动项；传 `bench=` 时自动插入"与基准线的对比"一节，**中文序号由计数器生成，插节不用手改后面所有编号** |
| 内容片段 | `_headline_verdict`、`_level_detail_table`、`_honesty_table`、`_glossary_table`、`_action_items` | 摘要文案；逐关明细（**数值与量纲分列**，防 `1.191-5` 这类拼接，原 `_fmt_value` 已合并）；样本量 vs 门槛；口径表；行动项 |
| Markdown 渲染 | `render_markdown` | 块 → Markdown，表格手写不依赖 tabulate（原 `_md_table` 已合并） |
| HTML 渲染 | `render_html`（转义与表格是一行式 `_esc`/`_md_inline`/`_html_table`） | 块 → 单文件自包含 HTML（图以 base64 内联，可直接发微信） |

### `export_excel.py` —— Excel 渲染器（2026-11-06 加）

| 组 | 成员 | 作用 |
|---|---|---|
| 主流程 | `excel_bytes`、`save_excel` | 读**同一份 sections** 出 xlsx 字节 / 落盘；UI 下载按钮直接吃字节 |
| 分派 | `_write_text_sheet`、`_write_data_sheet` | 文字/提示/清单归「报告说明」，每张 `TABLE` 块单独一个 sheet（带筛选+冻结） |
| 工具 | `_clean`、`_width`、`_sheet_name`、`_fit` | NaN/numpy 标量转可写值；中文按两格算列宽；sheet 名去「表 N」前缀、避非法字符与 31 字上限、去重 |

三个渲染器共享 sections，所以不会出现「MD 里 8 人、Excel 里 10 人」的口径打架。
图片不进 Excel，说明页留一行指向 HTML 版。报告里的「数值」列带了单位/量纲是字符串，
所以额外从 `meta["wide"]` 出一张「原始指标（可计算）」，全是原生 int/float，能直接算。

## 记忆口诀

> **契（L0）→ 入（L1）→ 算（L2+L3）→ 断（L4）→ 出（L5）→ 用（L6）**

- 想改"指标怎么算" → 只动 `metrics.yaml`，不动代码（L0 的 registry + L3 的 compute 自动生效）
- 想改"阈值多少算断崖" → 只动 `metrics.yaml` 的 `rules:`
- 想加一个字段 → `schema.py` 的 `FIELDS` 加一行 + `io_load.map_raw_column` 加别名
- 想加一种问法 → `cards.py` 加一张 `_card_xxx`，并在 `CARDS` 里登记关键词
- 想调"多少项目才给基准线""偏离多少才算异常" → 只改 `bench.py` 顶部的 `MIN_PROJECTS` / `MIN_DEVIATION_PCT`
- 想加一个页面 → `pages/` 下新建一个 `.py`，样式、数据源、缓存都从 `ui_common.py` 导入，别各自复制一份
