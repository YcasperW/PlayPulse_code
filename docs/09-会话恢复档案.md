## 1. 一句话

**PlayPulse · 把脉**：给游戏试玩数据做「难度体检」的工具。上传 CSV 直接出报告，
不等你提问；样本不够时明确拒绝给结论，而不是给一个漂亮的假结论。

不是 SQLBot / 通用 ChatBI 那类「问数」工具。核心判断是：**指标本体预定义，所以根本不需要
通用 Text-to-SQL**，LLM 只负责选分析卡片、填参数、解读结论。

真实目的：**求职作品集**。用户原话是「我需要这个项目来充实我的项目经历，数据少也要做」。
评判标准是项目完整度 + 可量化指标 + 可演示性 + 简历可写性。不要再劝退。

  上限 0.80 不取 1.0，否则会出现「新手高手快过老手中位」，抹掉标签区分度）
- `data/projects/` 有三个演示项目（星屿开箱/机械迷城/甜品消消乐），`data/bench/` 是基准库

## 5. 面试/答辩的三个谈点

1. **痛点①口径不统一 → 语义层**。14 个指标 + 2 复合 + 6 条规则全写死在
   `semantics/metrics.yaml`，改 YAML = 改口径，全项目生效、可 git diff、可 review，
   `registry` 还能导出成口径文档。
2. **痛点②分析人工成本高 → 上传即出报告**（report-first，不是 chat-first）+ 分析卡片复用。
3. **小样本诚实性**。样本量单位是**玩家不是行数**——先聚合到 (玩家×关卡) 再做 Bootstrap，
   否则置信区间假性收窄。≥8 人可下结论 / 5-7 人只给方向 / <5 人拒绝判断。
   用 Bootstrap 百分位法而非 t 检验（时长右偏）。

一句话路径论点：地基（语义层 + 统计层）在 MVP 就打完且不再动，V1 起所有新能力都长在它上面。
口径一改历史基准线全部作废——这解释了为什么「导 Excel / 加品类」可以后做，而「口径统一」必须先做。

## 6. 这台机器的环境坑（每次都会踩）

- **Bash 工具 PATH 损坏**：`ls` / `dirname` / `head` / `tail` / `cd` 都可能 command not found。
  开头先 `export PATH="/c/Users/Jochenwang/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:$PATH"`。
- **Python 必须用隔离 venv**：`C:\Users\Jochenwang\.workbuddy\binaries\python\envs\default\Scripts\python.exe`
  （pandas / numpy / matplotlib / scipy / openpyxl / streamlit 都装在这儿）。
  直接调 3.13.12 主解释器会报 no module named pandas。
- 跑命令要设 `PYTHONPATH` 指向项目根 `D:\杂\个人文件\个人项目\PlayPulse`。
- **PowerShell 工具在本机 stdout 捕获不到**，用 Bash 或让 Python 写文件再 Read。
- **中文路径操作一律写 UTF-8 的 Python 脚本执行**，别在 shell 里直接拼中文路径。
- pandas 3.x 变严：`df.loc[m,"int列"]=float数组` 会抛 LossySetitemError，先 `astype(float)`。
- Streamlit 1.64 起 `use_container_width` 被移除，统一用 `width="stretch"/"content"`。
- openpyxl：`ws.cell(row,col,value=None)` **不会清空**已有值，必须 `.value = None`；
  模板被外部编辑器另存后数据验证/条件格式范围会被压缩，须 clear + 重建。
- 报告 md5 对拍要先 `re.sub(r"\d{4}-\d{2}-\d{2} \d{2}:\d{2}", "<TS>", ...)` 抹掉时间戳，
  否则每次都不同。基线 `4bf76244fb0bc7c82bc996cae9c35548`。
