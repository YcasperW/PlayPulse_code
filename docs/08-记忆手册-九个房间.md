# 记忆手册：把代码讲成一个故事

> 这份文档跟 `05-代码地图.md` 是同一个东西的两种看法。
> 05 是字典（查"这个函数在哪"），这份是背诵用的（"整个项目在干什么"）。
> 想不起细节去翻 05/06，想不起全局看这份。

---

## 先说结论：你的记忆目标定错了

你记不住，不是因为分层分得不对，是因为你给自己的目标是**记住所有方法**。

105 个函数，靠看是记不住的，也没必要。真正要硬记的是：

- **10 个房间**（0 大门 + 9 个房间）
- **每个房间 3 个招牌函数**，一共 30 个锚点

剩下的 70 多个函数都是这 30 个的手下。你知道它归哪个房间、归谁管，
需要的时候翻 05/06 两分钟就能找到——这就够了。熟练工种不是背下所有零件，
是知道零件挂在车间的哪面墙上。

分层表解决的是"在哪儿"，故事解决的是"为什么是这个顺序"。
顺序比位置好记：人天生记故事，不记表格。

---

## 故事主线：一张乱表的一次旅程

一个策划拿着自己填的 Excel 来找你："我这游戏第 2 关是不是太难了？"

这张表从大门进来，走过 9 个房间，变成一份报告从大门交回去。
你只要记住这 9 个房间和顺序，整个项目的代码就都挂上去了。

房间顺序不是随便排的，它就是数据的流向：
**表 → 规范表 → 指标 → 带区间的数 → 判定 → 诊断 → 报告 → 追问 → 跟别人比。**

### 数字桩（先记这一句就够了）

> **大门挂号去分诊，翻完医典做化验；质控过了进诊室，写完病历去答疑，最后归档进档案。**

对应：0 大门、1 挂号、2 分诊、3 医典、4 化验、5 质控、6 诊室、7 病历、8 答疑、9 档案。

---

## 先分清楚：1 / 2 / 3 都在"变规整"，但规整的不是同一个东西

这是最容易卡住的地方。三个房间看着都像"把乱数据整理成标准信息密度"，
其实它们**碰的东西完全不一样**——按"处理对象"分，一秒就能分开：

| 房间 | 处理对象 | 碰不碰数据 | 打个比方 |
|---|---|---|---|
| **1 挂号** `schema.py` | **列名**（这一列叫什么） | 不碰，它是字典 | 办就诊卡：先确认"你叫什么、材料带没带齐" |
| **2 分诊** `io_load.py` | **数据行**（这一行有没有效） | 真的在读、在改 DataFrame | 分诊台：测血压、排队、把人理成一队 |
| **3 医典** `registry` + `expr` | **口径**（什么叫难） | 不碰数据行，只被问时给答案 | 教科书：不碰病人，只提供判据 |

**一句话分开它们：挂号管"列叫什么"，分诊管"行对不对"，医典管"怎么算"。**

代码上的硬证据（不用背，看一眼就信了）：

- `schema.py` **只有 2 个 def**（`explain_field` / `fields_of_layer`），剩下的全是静态字典：
  36 条 `FIELDS` 字段定义 + `ALIASES` 别名表 + `FIELD_BY_NAME` 索引。它从头到尾没读过一个 CSV。
- `io_load.py` 的 4 个 def 全在动 DataFrame（`map_raw_column` / `read_file` / `to_fact_table` / `load_auto`）。
- `registry.py` / `expr.py` 只处理 YAML 文本和公式字符串，签名里根本没有 `DataFrame`。

所以顺序是：**先有挂号的字典（列名标准）→ 分诊才能照着它翻表 → 化验才能照着医典的公式算。**
医典不在数据链路上，它是被化验科"查"的——这就是为什么它排在 3 而不是跟 1、2 混在一起。

### 顺便纠正一处：打分转数字不在化验科

你可能以为"化验科把用户的文本打分换算成数字"。**没有这一步代码。**
文本 → 数字是**采集阶段**干的，规则写在 `templates/编码字典-文本转数字.md`（"数字优先"），
策划填现场表的时候就该填数字。所以数据一进门已经是数字了。

化验科真正做的是：**按医典的公式，把字段算成指标**——它算的是"关卡耗时""卡关率"这些
表里根本不存在的新东西，不是把"有点难"翻译成 3。

## 0. 大门 —— `cli.py` / `app.py` + `pages/` + `ui_common.py`

**一句话**：人从这儿把表递进来，报告从这儿交回去。

| | |
|---|---|
| 接手 / 交出 | 接：一个文件路径。交：报告文件或网页 |
| 招牌 | `main`（CLI 分发）、`build_report` 调用处、`load_context`（Web 取数据） |

- CLI 和 Web 走的是**同一套后端**，只是两套窗口，不存在"网页版算得不一样"。
- Web 是多页的，跨页只能传**路径字符串**（`UploadedFile` 一离开上传页就废了）——这个坑写在 `ui_common.py` 顶部。
- 出问题先看这：命令能不能跑通 / 页面白不白。这里出问题是**入口问题**，不是算法问题。

## 1. 挂号处 —— `schema.py`

**一句话**：一份静态字典，只回答"这一列叫什么"，**不碰数据**。

| | |
|---|---|
| 接手 / 交出 | 接：什么都没有（它是配置）。交：字段定义 + 别名表 |
| 招牌 | `FIELDS`（36 条字段清单）、`ALIASES`（中文表头 → 规范名）、`FIELD_BY_NAME` |

- 跟 2 分诊的分工：**这里只有"标准"，没有"整理动作"**。真正的改名翻表是分诊台干的。
- 要加一个字段，第一站永远是这里。
- 三层字段（通用 / 品类 / 项目）的划分就在这，后面"通用层强制统一口径"这个决策的源头也在这。

## 2. 分诊台 —— `io_load.py`

**一句话**：照挂号的字典把表翻整齐，只管**行对不对**，不管**怎么算**。

| | |
|---|---|
| 接手 / 交出 | 接：任意 CSV / Excel。交：`Dataset` |
| 招牌 | `load_auto`（唯一入口）、`to_fact_table`（规范化七步）、`Dataset`（装结果） |

- 它是**唯一真的在读文件的房间**（xlsx 表头在中间这种脏活也在这）。
- 它不管指标：翻完之后表还是那些字段，一个指标都没算出来。
- 映射不上的列**报出来**，不静默丢掉——这是全项目的脾气，后面每个模块都这样。
- `to_fact_table` 里那七步（列名映射 → 元信息回填 → 类型强转 → 兜底 → 派生 → 区间体检 → 清理）不用背，
  知道它"把乱的弄整齐"就行。
- 出问题先看这：报告"数据体检"那一节列的问题，几乎全部来自这里。

## 3. 医典室 —— `semantics/metrics.yaml` + `registry.py` + `expr.py`

**一句话**：不在数据链路上，是**被化验科翻的参考书**——只回答"怎么算、多少算高"。

| | |
|---|---|
| 接手 / 交出 | 接：YAML 原文。交：`Ontology`（本体对象） |
| 招牌 | `default_ontology`（全局单例）、`to_markdown`（导出口径文档）、`safe_eval`（安全求值器） |

- 跟 1 挂号的分工：挂号管**原始字段**叫什么，医典管**派生指标**怎么算。
  一个管"材料清单"，一个管"判读标准"。
- 它不认识 `DataFrame`，所以别来这找数据问题的原因。
- `expr.py` 是白名单 AST 求值，**不用 `eval`**——口径来自配置文件，执行配置绝不能直接 eval。
- `registry.py` 在加载时就把所有公式校验一遍，别等跑报告时才炸。
- 出问题先看这：指标算错了 / 想改阈值改权重。**90% 的情况只需要改 YAML**。

## 4. 化验科 —— `semantics/compute.py`

**一句话**：照医典的公式**凭空造出新指标**（表里本来没有），每个数都带置信区间。

| | |
|---|---|
| 接手 / 交出 | 接：`Dataset` + `Ontology`。交：`LevelMetrics`（long 表 + wide 表） |
| 招牌 | `compute_level_metrics`（算全部指标）、`compute_composites`（复合指标）、`player_level_matrix`（玩家 × 关卡矩阵） |

- 它算出来的"关卡耗时中位数""卡关率"是**表里不存在的列**——这是它跟分诊台的根本区别：
  分诊只是把列翻整齐，化验是造新列。
- 三步走：行级公式求值（`eval_formula_rows`）→ 聚合到玩家×关卡 → Bootstrap 出区间。
- **最关键的一步**：Bootstrap 之前必须先聚合到（玩家 × 关卡）。
  不聚合的话，同一个人打 3 关会被当成 3 个独立样本，置信区间会假性收窄。
- 算不了的指标记进 `skipped` 并写原因，不默默跳过。
- 出问题先看这：某个指标算不出来（看 `skipped`）/ 区间宽得离谱（多半是没聚合）。

## 5. 质控科 —— `statsx.py`

**一句话**：这个数到底能不能信。

| | |
|---|---|
| 接手 / 交出 | 接：一组数。交：点估计 + 区间 + 判定 |
| 招牌 | `describe_sample`（描述一组）、`compare_two_groups`（对比两组）、`verdict_by_sample_size`（够不够格） |

- 三件套：Bootstrap 百分位 CI + Cohen's d + Mann-Whitney。
  不用 t 检验是因为试玩时长是**右偏**的，正态假设不成立。
- 三档判定：≥ 门槛可下结论 / 一半以上只给方向 / 再少就拒绝判断。
- **样本量单位是玩家数，不是行数。** 10 人 × 3 关 = 30 行，但 n 是 10。
- 出问题先看这：别人问"这个结论能信吗"。

## 6. 诊室 —— `insights.py` + `diff.py`

**一句话**：照规则下诊断；再帮你看改完一版数值是变难还是变易。

| | |
|---|---|
| 接手 / 交出 | 接：`LevelMetrics`。交：`Finding` 列表 / `VersionDiff` |
| 招牌 | `run_pulse_check`（体检总入口）、`detect_difficulty_jump`（断崖）、`version_diff`（版本对比） |

- 两类判断：跳变类（这一关是上一关的几倍）、阈值类（超过某个数）。规则都在 YAML 里。
- 每条发现必须带 `conclusion`（结论）+ `advice`（怎么改）——**通用 BI 只给前者**。
- `diff.py` 按关卡对齐两版，区间跨过 0 就明说"无法确认"。
- 出问题先看这："为什么这个异常没被检测出来"（看 YAML 里的规则阈值）。

## 7. 病历室 —— `report.py` + `charts.py`

**一句话**：先堆中间结构，再由 MD / HTML 两个渲染器各出一份。

| | |
|---|---|
| 接手 / 交出 | 接：`PulseCheck` + 可选的 diff / bench。交：`Report`（md + html） |
| 招牌 | `build_report`（编排）、`render_markdown` / `render_html`（两个渲染器） |

- 中间结构（H / P / CALLOUT / TABLE / IMG / LIST 六种块）是刻意的：
  不这么做迟早写成两套逻辑，然后出现"MD 里 n=8、HTML 里 n=10"。
- 图是 matplotlib 画的再转 base64 内联，**不用前端图表库**——报告要能导出成自包含单文件。
- 章节编号是自增的（`_sec` + `_CN_NUM`），插一节不用手改后面全部编号。
- 出问题先看这：报告长什么样 / 图出不出现。

## 8. 答疑台 —— `cards.py`

**一句话**：**复诊窗口**——拿着诊室已经写好的病历，回答你追着问的那句话。

| | |
|---|---|
| 接手 / 交出 | 接：一句人话 + `pc`（诊室的结果）。交：`CardResult` |
| 招牌 | `ask`（入口）、`route_intent`（关键词路由）、`fallback_card`（兜底） |

**答疑台到底在干嘛**（这是最容易说不清的一间，三句话讲完）：

1. **它不重新化验。** 看签名就知道：`ask(pc, question, onto)` 吃的是 `pc`，
   也就是诊室已经算好的 `LevelMetrics`。它只是把同一批数字**换个角度重讲一遍**——
   诊室说"第 2 关有问题"，你追问"那哪关最难"，它去同一个结果里翻给你看。
2. **它不新增判读逻辑。** 诊室是**不问自答**（6 条规则自动扫全表，主动报问题）；
   答疑台是**有问才答**（11 张卡片，你不问它不动）。
   一个是体检医生，一个是报告解读窗口。
3. **只有一个例外会回头碰原始数据**：`_card_segment`（新手 vs 老手分组）
   会回到 `pc.dataset` 重新切片再算一次矩阵——因为"按人分组"这个切法诊室没做过。
   记住这一个例外，其余卡片全是复用。

- 只做意图路由，**不生成 SQL**（决策 D1）。路由错了用户一眼看出来，
  口径错了看不出来——后者贵得多。
- 答不上就 `fallback_card`，明说"这个我答不了，目前能答的是这些"——
  **不猜**。口径不明的假答案比答不了贵得多。
- 11 张卡片不用背，记住分类就行：
  **找关**（哪关最难 / 最顺 / 哪关在赶人）、**看形**（曲线 / 通关时长）、
  **问因**（为什么卡住 / 卡住选什么）、**分层**（新手 vs 老手）、
  **可信**（能信吗 / 口径是什么）、**感知**（觉得难还是真的难）。
- 出问题先看这："这个问题它答不了"——看是不是该加一张卡片。

## 9. 档案库 —— `bench.py`（PlayBench）

**一句话**：跟别的病人比，你这一关在同类里排什么位置。

| | |
|---|---|
| 接手 / 交出 | 接：一次体检结果。交：`BenchCompare`（本次 vs 基准线） |
| 招牌 | `save_run`（存）、`build_baseline`（建线）、`compare_to_baseline`（比） |

- 三条规矩：**一个项目一个目录**（目录即隔离边界）、**一个项目一票**（取最近一次，测多了不算多票）、
  **只比通用层指标**（品类层跨项目比没意义）。
- 项目数不到 3 个就不给基准线，直说"攒不够"——跟小样本拒绝下结论是同一套逻辑。
- 只存点估计，**不存原始行**。
- 出问题先看这：基准线对不上 / 项目数不够。

## 三个记忆钩子

### 钩子一：反问句（面试最好用）

每个"为什么"都直接指向一个房间。答得出为什么，就答得出在哪。

| 反问 | 指向 |
|---|---|
| 为什么样本量按玩家不按行数？ | 5 质控科 |
| 为什么 Bootstrap 前要先聚合到玩家 × 关卡？ | 4 化验科 |
| 为什么不生成 SQL？ | 8 答疑台 |
| 为什么通用层口径必须强制统一？ | 9 档案库（不然基准线没法比） |
| 为什么报告要先做中间结构？ | 7 病历室 |
| 为什么报告里的图不用 ECharts？ | 7 病历室（要能导出单文件） |
| 为什么答不了的问题要直说答不了？ | 8 答疑台 |
| 为什么列名映射和指标公式要分两个文件？ | 1 挂号管"列叫什么"，3 医典管"怎么算" |
| 为什么医典室不读 CSV？ | 3 医典（它是参考书，不在数据链路上） |
| 为什么答疑台不重新算指标？ | 8 答疑台（它吃 pc，是复诊窗口） |
| 打分文本是在哪一步变成数字的？ | **不在代码里**——采集阶段，按编码字典填数字 |

### 钩子二：一句话咒语（每个房间一句，加起来 10 句）

```
0 大门   人从这进，报告从这出
1 挂号   只有标准，不碰数据（管列叫什么）
2 分诊   只翻行，不算指标（管行对不对）
3 医典   参考书，不在链路上（管怎么算）
4 化验   造新列，不是翻旧列；先聚合再算区间
5 质控   够不够格，我先说清楚
6 诊室   不只说哪里有问题，还说怎么改
7 病历   一堆中间块，两个渲染器
8 答疑   拿现成结果换个角度讲，答不了就直说
9 档案   一个项目一票，不到 3 个不给基准线
```

前三句连起来就是一句：**列叫什么（1）→ 行对不对（2）→ 怎么算（3）。**

### 钩子三：数据流顺口溜

> **表进来 → 对列名 → 理成行 → 查医典 → 算成数 → 盖可信章 → 下诊断 → 写病历 → 答追问 → 比同类**

九步对应 1-9 号房间（"表进来"是大门，不算在九间里）。
前三步最容易压成一个，**记住它们中间有两道坎**：列名是一道（1），行是一道（2），医典是第三道（3）。

## 怎么复习（15 分钟一轮）

1. 默写 10 个房间的顺序和一句话咒语（3 分钟）。卡住就看顺口溜。
2. 每个房间默写 3 个招牌函数名（5 分钟）。写不全的去翻 05。
3. 随机抽 3 个反问句，不看文档回答"在哪个房间、为什么"（4 分钟）。
4. 剩下时间：挑一个房间，打开对应文件，看它的函数是不是都围着那 3 个招牌转。

能默到第 2 步就够用了。第 3 步是面试用的。
