# 03 · 指标与埋点字典

> 用途：PlayPulse 的语义层设计输入。**指标本体是什么，决定了产品能问什么问题。**
> 状态：V0.1（2026-09-18），以休闲开宝箱品类为首个落地场景，后续按三层结构扩展。

---

## 1. 五层指标体系

| 层 | 回答什么问题 | 代表指标 |
|---|---|---|
| L1 留存 | 玩家还回来吗 | D1/D7/D30、会话频次、自然停止点 |
| L2 进度 | 玩家卡在哪 | **关卡流失漏斗**、卡关时长分布、资源缺口、卡关三选一 |
| L3 核心循环 | 开箱爽不爽 | 掉落实测分布 vs 配置概率、稀有物首获时间、开箱间隔曲线 |
| L4 变现 | 钱从哪来 | 广告渗透率、看完广告 vs 未看的留存差、付费时机 |
| L5 诊断 | 为什么 | 时间膨胀系数、客观/感知一致性、跳变比 |

### 关于「每关通关时间」

**它是弱指标，甚至有误导性。** 在开宝箱品类里没有操作门槛，时长基本是「数值 / 产出速率」的函数——把产出调高 10%，时长就掉一截，跟体验好坏关系不大。

正确用法：**当校验指标**（实际耗时 vs 设计耗时），不是优化目标。

---

## 2. L2 进度层：替代「通关率」的东西

休闲游戏没有通关率，替代它的是：

- **关卡流失漏斗**：进入第 N 关的人里，有多少再也没打开第 N+1 关。这是难度曲线的体检报告。
- **卡关时长 + 资源缺口**：区分「自然节奏」和「被数值墙卡死」。同样卡 3 分钟，「边开箱边攒资源」和「干等」是两种体验。
- **卡关三选一**：看广告 / 付费 / 直接退出。这个分布直接决定变现位怎么设计。
- **魔法关卡数**：横轴 = 玩家首日打到第几关，纵轴 = 后续留存，通常是**倒 U 形**。
  - 左侧低：玩太少，没进心流就走了（引导没勾住）
  - 峰值：意犹未尽 → 把大多数玩家"送"到这里
  - 右侧低：内容被吃光 / 疲劳 → 需要减速带（体力、等待、数值墙）
  - **找到峰值在第几关，用数值把首日进度往那推——这是数值调优最省力的杠杆。**

## 3. L3 核心循环：最常被漏掉的一层

| 指标 | 为什么重要 |
|---|---|
| **掉落实测分布 vs 配置概率** | 验证随机算法与保底是否真生效。不埋这个，数值 bug 你永远发现不了——玩家只会默默流失 |
| **稀有物首获时间（Time to first epic）** | 拿到第一个稀有物的玩家留存显著更高。这是**可以主动设计**的钩子，试着把首爆提前到前 5 分钟 |
| **开箱间隔曲线** | 会话内相邻两次开箱的时间差。间隔越来越长 = 厌倦的**领先指标**，比真实流失早 2–3 天出现 |

---

## 4. L4 变现层

- **广告渗透率**（有多少比例的人看过广告）比人均观看次数更能说明问题。
- **看过广告 vs 没看过广告的次日留存对比**：不是所有广告收入都是好收入。若看过那组留存明显更低，说明点位或频次在赶人。

## 5. 埋点事件表（最小 15 个）

| 优先级 | 事件 | 关键参数（别省） |
|---|---|---|
| P0 | `chest_open` | 宝箱类型、消耗资源、产出物品 + 稀有度、**是否触发保底**、当前关卡、累计开箱数、是否广告箱 |
| P0 | `level_start` | 关卡 ID、进入时资源、尝试序号 |
| P0 | `level_complete` | 关卡 ID、耗时、尝试次数、本关开箱数、剩余资源 |
| P0 | `level_fail` | 关卡 ID、失败原因、已尝试次数 |
| P0 | `ad_impression` / `ad_complete` | 点位、广告类型、是否看完、看完后 60 秒内行为 |
| P0 | `session_start` / `session_end` | 时长、开箱数、进出时的关卡 |
| P0 | `tutorial_step` | 步骤号、完成 / 跳过 |
| P0 | `purchase` | 商品、金额、**购买时机（是否卡关中）** |
| P1 | `resource_change` | 资源流水（校验经济系统有没有通胀） |
| P1 | `ui_exit` | 退出时停留在哪个界面 |
| P1 | `item_first_get` | 稀有物首次获得时间 |

> **铁律**：`chest_open` 一定要带上下文参数。只埋一个「开箱次数」，后面所有分层分析都做不了。

## 6. 三层指标本体（跨项目复用的前提）

```
┌─ 通用层（强制统一口径）─────────────────────┐
│ 会话时长 / 关卡进度 / 卡关事件 / 留存 / 付费      │
│ → 这一层不统一，20 个项目就是 20 套字段名，基准线永远算不出来 │
└──────────────────────────────────────┘
┌─ 品类层（休闲 / 卡牌 / 放置 / 益智 …）────────┐
│ 休闲：开箱次数、掉率、稀有物首获                  │
│ 卡牌：抽卡、养成深度、阵容强度                    │
└──────────────────────────────────────┘
┌─ 项目层（本项目自定义）─────────────────────┐
│ 特定玩法事件、活动指标                          │
└──────────────────────────────────────┘
```

**为什么必须分层**：开宝箱的「卡关」和卡牌游戏的「卡关」根本不是一回事。通用层保证基准线能算，品类层保证语义准确，项目层保证灵活性。

## 7. 未上线阶段的替代指标（内部试玩专用）

真实留存测不了（同事是"给面子玩"，不会真流失），用这三个代理指标：

| 代理指标 | 做法 | 判读 |
|---|---|---|
| **无激励额外游玩时长** | 告知「测 20 分钟就行」，暗中计时、不提醒 | 超出部分 ≈ 真实动机；提前问「可以结束了吗」= 明确负信号 |
| **次日自发回归** | 第一天明确说「测试结束了」，第二天不提醒、不发消息 | 10 人里 2 人自发回来，比 10 人全说「好玩」更有说服力 |
| **自然停止点** | 观察开始敷衍的时刻（乱点、跳过动画、看手机、问「还有几关」） | 该时刻的关卡 + 时长 = 准流失点 |

详见 `02-数据采集方案-内部试玩.md`。

## 8. 本文件与产品的关系

PlayPulse 的「领域语义层」就是把上面这些指标**编码成可版本化的配置**（指标名、计算公式、所需字段、适用品类、样本量门槛）。

- 通用层指标 → 内置，不可改（保证基准线口径统一）
- 品类层指标 → 以配置包形式提供，新品类接入 = 新增一个配置包（目标 1–2 天）
- 项目层指标 → 项目组自己加

这份字典就是那个配置包的**第一版草稿**。
