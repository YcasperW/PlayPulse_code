# 休闲开宝箱小游戏 · 上线前内部测试数据采集方案

> 适用阶段：未上线、无真实用户、只能拉同事做小样本测试
> 核心原则：**只测小样本下能测准的东西，不要假装测出了留存**

---

## 0. 先明确：哪些东西现在测不了

| 指标 | 为什么测不了 | 别自欺的做法 |
|---|---|---|
| D1 / D7 / D30 留存 | 同事是"给面子玩"，不会真的流失 | 用下方三个代理指标替代 |
| 付费率 / ARPPU / LTV | 没人会真花钱，且无真实消费场景 | 只问意愿，且只能做版本间相对比较 |
| 广告渗透率 / eCPM | 需要真实流量与广告填充 | 跳过，上线后测 |
| 掉率精确性验证 | 样本量太小，统计上不显著 | 只做"有无明显 bug"的粗检（如某稀有物 200 次未出） |
| 长期数值平衡 / 通胀 | 需要数周数据 | 靠数值模型推演 + 短期资源曲线外推 |

**能测准的**：单局客观行为、难度曲线、引导可达性、经济系统短期走势、定性体验反馈。

---

## 1. 三个留存代理指标

### 1.1 无激励额外游玩时长（最硬的信号）
- 告知："测 20 分钟就行"
- 暗中计时，**不做任何提醒**，记录实际停止时间
- 判读：超出 20 分钟的部分 ≈ 真实动机；提前询问"可以结束了吗" = 明确负信号
- 注意：不能让被测试者知道你在计这个，否则失效

### 1.2 次日自发回归（最接近 D1）
- 第一天结束时明确说"测试结束了"，**不要安排第二天**
- 第二天不发任何提醒、不发消息
- 观察是否自发打开游戏（后台可查，或第二天再问"你后来自己打开过吗"）
- 判读：10 人中有 2 人自发回归，比 10 人全说"好玩"更有说服力

### 1.3 自然停止点
- 同事不会真流失，但会**敷衍**
- 观察信号：开始乱点、跳过动画、看手机、问"还有几关"、重复无意义操作
- 记录该时刻的**关卡数与已用时长** → 这就是他的"准流失点"

## 2. 难度数据采集

### 2.1 客观难度（每关一行记录）

| 字段 | 说明 | 为什么重要 |
|---|---|---|
| 关卡 ID | — | 主键 |
| 关卡耗时 | 进入 → 通过的总时长 | 基础 |
| **主动推进时长** | 有操作、有反馈的时间 | 与卡关时长分开看才有意义 |
| **卡关时长** | 停滞、干等、无反馈的时间 | 折磨感的主要来源 |
| 尝试次数 | 失败重开次数 | 硬卡点判定 |
| 本关开箱次数 | 这一关开了几个箱子 | 开箱游戏的核心消耗度量 |
| 资源缺口 | 卡住时还差多少资源 | 判断是数值墙还是设计意图 |
| 无效 / 误操作次数 | 点错、找不到按钮 | UI 可达性问题 |
| 求助次数 | 问策划 / 看提示 | 引导有效性 |
| 是否使用加速 / 广告 | 是 / 否 | 变现位自然触发率 |

### 2.2 感知难度（主观，打完立刻问）

每关结束立刻问，**最多 3 个问题**，否则测试变成负担：

1. 这关难度打分（1–7 分）
2. 挫败感（1–5 分）**与** 挑战感（1–5 分）——**两个独立的分，不要合并**
3. 你觉得自己卡住是因为什么（开放，可空）

> 关键：必须**打完就问**，不能玩完 30 关再回忆。回忆会被峰终效应污染，只剩最后一关的印象。

### 2.3 时间膨胀系数（枯燥检测器）

每关打完让被测试者**预估**自己花了多久，再除以真实耗时：

| 系数 | 含义 | 处理 |
|---|---|---|
| ≈ 1.0 | 正常 | — |
| > 1.3 | 体感比实际长 → 枯燥 / 重复 / 等待 | 高风险关卡，优先修 |
| < 0.8 | 体感比实际短 → 心流 | 好事；但若全关卡都如此，需检查是否只是无决策的挂机消耗 |

> 这个指标能抓到"数据上不难、玩起来很煎熬"的关卡——纯看耗时永远发现不了。

### 2.4 难度曲线（关卡之间的关系）

- 计算相邻关卡的**耗时跳变比**与**尝试次数跳变比**
- 跳变 > 1.5 倍 = 断崖，是流失高发点
- 目标形状：**锯齿上升**（有起伏、有喘息），不是直线上升，也不是长期平台

### 2.5 卡关归因（决定怎么修）

把每一次卡住归到以下五类，**归因错误会导致乱调数值**：

| 归因 | 修法 |
|---|---|
| 资源不够 | 调产出 / 调消耗（数值问题） |
| 概率不好（脸黑） | 加保底 / 降低方差（随机性问题） |
| 没看懂规则 | 改引导 / 改 UI 提示（信息问题） |
| 操作繁琐 | 减步骤 / 加一键（交互问题） |
| 不知道要干嘛 | 改目标呈现（动机问题） |

## 2.6 量化优先：把所有能变成数字的都变成数字

> **核心原则：能编码的绝不自由填。开放题回收率高，但 10 份问卷做不出任何统计结论。**

### 三类「假数据」，是数字不够的真正原因

| 症状 | 例子 | 改法 |
|---|---|---|
| 本可量化却用了开放题 | "你觉得卡住是因为什么？"（填空） | 改成 1–5 编码，原文只在备注列留档 |
| 绝对评分没有锚点 | "这关难度 1–7 分" | 改问**相对上一关** −2~+2，跨人可比 |
| 只问不记行为 | 问"操作顺不顺" | 直接数：总操作数 / 无效操作数 / APM / 停顿次数 |

### 关键改造一：绝对分 → 相对增量

绝对打分（1–7）的问题是**每个人锚点不同**，10 个人 10 套标准，均值没有意义。

改问：**"这关比上一关难多少？"** −2 容易很多 / −1 / 0 差不多 / +1 / +2 难很多。

好处：自带基线校准，跨人可比；累加后得到**感知难度曲线**，可与客观耗时曲线叠图，找两者背离的关卡。

### 关键改造二：加一层「行为数字」（现场数不过来的，回看录屏补）

这些是**不用问就能拿到的数字**，比自评更硬：

| 字段 | 怎么来 | 能发现什么 |
|---|---|---|
| 总操作数 / 有效 / 无效 | 录屏回看计数 | 无效操作率高 = UI 找不到、误触 |
| **APM**（每分钟操作数） | 操作数 ÷ 时长 | 骤降 = 卡住或挂机；骤升 = 烦躁乱点 |
| 最长单次停顿 | 录屏 | 停滞感的直接度量 |
| 停顿 > 5 秒的次数 | 录屏 | 干等的次数，比总卡关时长更敏感 |
| 跳过动画 / 引导次数 | 录屏 | 内容被当成障碍 |
| 切屏 / 看手机次数 | 录屏 | **最强的厌倦信号**，比任何自评都真 |
| 口头抱怨次数 | 录屏 | 挫败的即时反应 |

### 关键改造三：强制选择代替意愿提问

不要问"你愿意付费吗"（人人都会说看情况），改问**只能选一个**：

> 卡住了，只能选一个：1=继续等 2=看 15 秒广告 3=花 6 元 4=直接退出

选 4 的人 = 准流失。**这个分布直接告诉你变现位该不该加、加在哪。**

### 关键改造四：感知掉率

让玩家填"你觉得下一个箱子出稀有的概率是 ___%"，与配置值对比：

- 偏差 < −15pt：保底没被感知到，或稀有反馈太弱
- 偏差 > +15pt：预期被吊高，后面必然失望

### 配套文件

- `templates/逐关-现场填写表.csv` —— 现场能填的 16 列，全数字/编码
- `templates/逐关-录屏回看编码表.csv` —— 事后补的 11 列行为数字
- `templates/编码字典-文本转数字.md` —— 所有编码规则（**必须提前定好**）
- `templates/整体问卷-模板.md` —— 10 问里 9 问产出数字

> **分成两张表的原因**：现场根本数不清 APM 和停顿次数，硬填只会得到假数据。
> 现场只记能记的，行为数字统一回看录屏补——录屏本来就要录（见 4.2）。

## 3. 难度四象限诊断

把**客观难度**（耗时 / 尝试 / 开箱数）与**感知难度**（1–7 分自评）交叉：

| | 客观低 | 客观高 |
|---|---|---|
| **感知高** | 假性难度：玩家不知道自己在推进 → 强化进度反馈与预期管理 | 真实卡点：数值墙 → 降数值，或给广告 / 提示做救济 |
| **感知低** | 顺滑但可能无聊：缺节奏起伏 → 插入小高潮 | 心流，或无感消耗 → 追问是否享受，再加回访钩子 |

**客观与感知不一致的关卡，就是设计问题所在。**

## 4. 测试流程 SOP

### 4.1 样本
- 总数 8–10 人
- 构成：策划 6–8 人 + **至少 2 个非策划**（行政、运营、家人）
  - 这 2 个人的反馈，往往比 8 个策划更接近真实玩家

### 4.2 单次会话
1. 各自在工位玩，不围观（避免霍桑效应）
2. 录屏（比站旁边看更真实，也便于回看）
3. **前 10 分钟不许提问**——你能因此看到他到底能不能自己搞懂
4. 每关结束填一行记录表
5. 明确告知"测 20 分钟就行"，随后暗中计时（见 1.1）
6. 全部结束后 5 分钟整体问卷

### 4.3 次日
- 不提醒、不安排，观察自发回归（见 1.2）

## 5. 同事样本的 5 个偏差与缓解

| 偏差 | 表现 | 缓解办法 |
|---|---|---|
| 专业偏差 | 看得懂数值，真玩家看不懂 | 前 10 分钟禁问，观察能否自助搞懂 |
| 讨好偏差 | 不好意思说难听的 | 书面匿名问卷；**投射法**提问（见下） |
| 霍桑效应 | 被盯着就更认真 | 录屏而非围观，各自在工位玩 |
| 耐受力偏差 | 策划能忍的数值墙，真玩家早跑了 | 投射法："你觉得普通玩家第几次失败会卸载？" |
| 样本同质性 | 全是策划，无多样性 | 至少拉 2 个非策划 |

### 投射法（核心技巧）
不要问"你觉得难吗"，改问**"你觉得一个普通新手玩家会怎么想 / 会在哪里放弃"**。
让人评价"别人"时戒心显著降低，实话更容易出来。

## 6. 记录表模板

### 6.1 逐关记录表（每人一份，每关一行）

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | | | | | | | | | | | | | | | |
| 2 | | | | | | | | | | | | | | | |

### 6.2 整体问卷（玩完后）

1. 你自然玩了多久？（不告知实际计时）——用于计算时间膨胀
2. 你是从第几关开始觉得"不想玩了"的？为什么？
3. 最想跳过的部分是哪一段？
4. 明天你还会自己打开这个游戏吗？（1–5 分）
5. 你会推荐给朋友吗？（1–5 分）
6. 你觉得一个普通新手玩家，会在第几关流失？为什么？
7. 开箱最爽的一次是什么时候？最没感觉的一次呢？

## 7. 测试后怎么分析

1. **画难度曲线**：横轴关卡，纵轴耗时 / 尝试次数，标出跳变 > 1.5 倍的断崖点
2. **画四象限散点**：每关一个点，客观难度 vs 感知难度，重点看偏离对角线的关卡
3. **排时间膨胀系数**：从高到低，前 3 名优先修
4. **卡关归因归类**：五类各占多少，占比最高的那类决定你的主要修法方向
5. **交叉验证**：把"自然停止点"和"难度曲线断崖点"叠在一起看——两者重合的位置，就是上线后真实的流失点

---

## 8. 一句话总结

上线前不要试图测留存，测**难度曲线的形状、断崖的位置、以及客观与感知不一致的地方**。
同事不会真的流失，但他会在敷衍的那一刻告诉你真相。
