## 二、为什么需要合成

真实数据只有 6 行，无法支撑任何统计与诊断链路。合成的目的是**跑通系统、压测、演示**，不是替代真实数据。

## 三、生成方式

脚本：`scripts/gen_synthetic_playtests.py`
随机种子：`SEED = 20260921`（固定，可完整复现）
重跑：`python scripts/gen_synthetic_playtests.py`（会覆盖同名文件）

改规模只需改两个常量：

```python
LEVELS_PER_FILE = 3    # 每份文件的关卡数（当前游戏只有 3 关）
N_FILES = 50           # 每个类别生成多少份
```

离群个体（见第五节）的数量与迁移幅度也可调：

```python
OUTLIER_COUNT_RANGE = (3, 7)      # 每类抽几个离群个体
OUTLIER_LAM_RANGE   = (0.55, 0.80)  # 离群个体向对面类迁移的比例
```

## 四、建模依据

所有参数由现有 2 份真实样例反推，不掺主观假设。

游戏只有 3 关，因此**不做公式外推**：真实样例的逐关观测值直接当作该类的**分布中位数**，再叠加噪声。

| 指标 | 建模方式 |
|---|---|
| 耗时 | 该玩家逐关目标值 × 对数正态噪声 |
| 卡关占比 | 该玩家逐关目标值 + 高斯噪声，截断到 [0, stuck_max] |
| 尝试次数 | 该玩家逐关目标值 + 高斯噪声，最小 1 |
| 难度增量 | 首关固定 0；其后按权重抽样，以 +1 为主，新手常出现 +2（断崖） |
| 挫败感 / 挑战感 | 逐关目标值 + 噪声，截断到 1–5 |
| 预估耗时 | 逐关膨胀比目标值 + 噪声，取整到 10 秒（人类估计习惯）。老手接近实际（0.97–1.33），新手系统性低估自己花的时间（0.59–0.82） |
| 卡关原因 | 新手偏「不知道干嘛 / 没看懂规则」；老手偏「概率不好 / 操作繁琐」 |
| 卡关选择 | 挫败感越高，「想退出」权重越大 |

## 五、个体异质性（避免"每类都一个样"）

若只按类别中位数加噪声，会得到「每个新手都一样菜、每个老手都一样强」的不真实分布。因此引入**玩家级的漂移系数 λ**：

| λ | 含义 |
|---|---|
| 0 | 本类的典型水平 |
| 1 | 完全变成对面类的典型水平 |
| < 0 | 比本类典型**更**典型（更强的新手 / 更菜的老手） |

- **普通个体**：λ ~ N(0, 0.10)，截断在 [-0.25, 0.25]。差异落在目标值上而非噪声上，所以同一位玩家的三关会一致地偏快或偏慢。
- **离群个体**：λ ~ U(0.55, 0.80)，即「新手里玩得好的 / 老手里玩得菜的」，每类随机抽 3–7 个（本次各 4 个）。
- λ ≥ 0.45 时，该玩家的主观分布（难度感知、卡关原因、卡关选择）也切成对面类别的——玩得好的人归因方式也更像老手。

**上限为什么是 0.80 而不是 1.0**：λ=1 会让「新手高手」快过老手中位数、「老手菜鸟」慢过新手中位数，把两个类别本身的区分度抹掉。0.80 时刚好落在对面类的中后段。

## 六、局限性

1. **没有弃游建模**。真实玩家反复卡关后大概率流失，合成数据里所有玩家都打完了 3 关，因此会高估后段关卡的样本量。
2. **同一版本**。全部为 `V1`，不含版本间的参数改动，暂不能用于版本对比 Diff 的验证。
3. **玩家画像仍是两档**。虽然加了个体漂移，但「老手/新手」仍是离散标签，没有「玩过同品类」「接触过同类玩法」等中间层；漂移系数 λ 是人为设定的连续量，不是从真实数据拟合出来的。
4. **离群个体是刻意植入的**，其数量与幅度由 `OUTLIER_COUNT_RANGE` / `OUTLIER_LAM_RANGE` 控制，不代表真实人群里离群者的实际比例。
5. 真实数据仅 6 行（2 位玩家），分布参数的可信度有限；**拿到更多真实试玩数据后应重新标定 PROFILE 常量**。
