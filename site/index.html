PlayPulse · 把脉

游戏试玩数据难度诊断工具

面向未上线游戏的自动化难度评估与卡关归因

本项目面向游戏试玩阶段的难度评估需求，提供一套可复现的自动化分析流程。使用者上传试玩数据后，系统无需交互提问即可生成诊断报告，定位难度陡增的关卡、分析卡关原因并给出调整建议；当样本量不足以支撑统计推断时，系统不给出确定性结论，而是标注该结论的可信边界。

一、设计要点

指标口径统一定义

全部指标集中定义于一份 YAML 语义层，包含 14 项基础指标、6 条判定规则与 2 个复合指标；「关卡难度」等概念均有固定算法。由于指标本体预定义，系统不需要通用 Text-to-SQL，可避免自然语言转 SQL 带来的口径偏差。

报告优先的交互方式

通用 BI 通常假设使用者已明确分析目标，而试玩阶段的策划难以预先提出具体问题。本项目将「上传即出报告」设为默认动作，问答仅用于选取预定义分析卡片与解读结论。

多格式同源输出

Markdown、HTML 与 Excel 三种格式由同一份内容结构渲染，确保各版本的指标口径与结论一致。

二、报告输出内容

以下列出报告包含的分析维度。具体数值、检出结论与关卡结构取决于每次上传的数据，不构成固定标准。

  • 难度断崖：以相邻关卡耗时倍数识别难度陡增，判定阈值在语义层中配置。
  • 硬卡点与准流失：依据卡住时长与退出占比标记风险关卡。
  • 卡关归因：区分信息问题（引导说明不清）与数值问题（难度设定过高），避免归因偏差导致错误调参。
  • 可信边界：每个估计值附置信区间与样本量；样本不足时，结论标注为方向性参考。

三、功能模块

  • Pulse Check（难度体检）：上传 CSV 后自动生成诊断报告，主流程已完成完整流程验证。
  • PlayBench（跨项目基准线）：架构已就位。目前仅 1 个项目具备游戏数据，基准库内项目均为合成派生数据，仅用于验证链路，不构成行业基准。
  • Signal / Noise（小样本诚实性）：实现 Bootstrap 置信区间、效应量与样本量门槛。

四、数据说明与使用边界

本项目所用试玩数据，以及页面展示的示例报告，均为合成 / 仿真数据，用于验证分析链路，并非真实玩家记录。项目尚未上线，不存在线上效果数据，亦无可引用的业务提升比例。跨项目基准线部分目前不具备真实数据支撑，相关结果不作为行业基准使用。

报告中的具体数值、检出结论与关卡结构均随每次上传的数据而变化，本页不列举任何一次样例结果作为固定标准；示例报告仅用于展示输出形态与版式。

五、本地运行

pip install -r requirements.txt
python -m playpulse check <你的试玩数据.csv>
streamlit run app.py

依赖清单见 requirements.txt。首条命令在 out/ 目录下生成 Markdown、HTML 与 Excel 三份报告；第二条命令启动多页 Web 界面。仓库内附有一份合成样例数据（见 data/raw/），可直接用于试跑。
